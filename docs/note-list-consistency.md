# 笔记列表的一致性与浏览位置

列表采用稳定的浏览窗口：后端决定查询顺序，前端保存已加载的卡片与游标。
它不是数据库快照，翻页仍然查询当前索引。

## 更新规则

- 普通编辑更新原位置的卡片，不重新排序、不插入未加载记录。
- 排序字段、成员关系或未知范围发生变化时，保留当前浏览窗口，切换查询或重新进入列表后再获取新顺序与成员。
- 后台失效不把多页列表替换成第一页。当前查询尚未加载时允许自动续载，保证冷索引准备完成后恢复显示。
- 显式刷新或切换查询建立新会话，重新接受后端的顺序与游标。
- 当前窗口主动创建笔记时，将新卡片放在开头；下次查询恢复后端顺序。

## 职责

- `NoteService::list_indexed_page`：桌面端只读分页。索引未就绪返回 pending，由后台准备。CLI 的同步准备入口保持独立。
- `memo-list-refresh-service`：合并同路径通知、取消被取代的读取；没有新通知时，读取失败最多重试两次。最终失败返回明确结果；尚未加载的查询允许自动恢复。当前窗口的保存立即更新卡片，后台卡片通知按 24ms 固定窗口批量提交，同路径保留最后一条。
- `NoteListSession`：拒绝过期分页响应，保存当前会话中的变更。批量更新与单卡更新共享投影逻辑。
- `note-list-projection`：按路径批量合并更新、删除及移动，保留加载顺序和未变化卡片的引用。
- Todo 是从最新 Markdown 正文重建的 `{ content, status }` 投影；不分配任务 ID，旧 ID 注释只在读取时剥除。
- 列表使用浏览器原生滚动行为，不接入自定义滚动锚点，避免在渲染、滚动及尺寸变化时同步扫描和测量卡片。

## 路径移动

移动通知先同步更新加载记录和会话中的路径身份，再异步读取元信息。
目录移动也作用于随后到达的旧分页记录。元信息读取被取消、合并或失败时，已经确认的移动身份仍然有效。

## 边界

实时索引中的记录可能跨过旧游标，未加载记录也可能新满足筛选；下一次列表查询会重新获取这些变化。当前会话保留已加载窗口，避免自动重查改变用户位置。
自定义筛选暂时在原始分页后执行，插件视图暂时全量读取。下沉后端可作为独立查询协议优化，不与编辑局部更新混合实施。
会话 overlay 尚无后端记录版本；它优先保护已收到的变更，显式刷新后重新接受索引结果。

编辑后的卡片仍在原位置更新，但不再通过自定义锚点补偿卡片高度变化；原生 WebView 的图片布局和惯性滚动仍需要实际交互验证。
